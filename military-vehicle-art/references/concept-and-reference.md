# Concept and reference discipline

## Generation is design, not reconstruction proof
Use Codex's actual image-generation capability and current installed guidance when the approved route calls for generation. If unavailable, disclose that capability gap and ask once whether to use supplied designs or an explicitly authorized drawn/Blender design proposal instead. Do not invent a generated image, silently substitute an unapproved route, or install/use a paid API or image-to-3D service. This guide's vehicle examples do not restrict the general asset scope.

Start with one informative concept rather than a batch of unrelated variants. Use [the concept prompt](../assets/concept-prompt.md), filling meaningful fields. Save the actual output, prompt, available settings, and version to the job. Do not claim undocumented seed/model settings. Inspect the result before asking approval.

An approved generated image guides fictional appearance. Photographs, authenticated drawings, and reliable measurements govern real vehicle identity. For real subjects, identify a specific variant/operator/period or a deliberately unmarked generic configuration; don't blend conflicting configurations. Record sources for visible variant-defining features. If reliable evidence is unavailable, label the uncertainty instead of claiming historical coherence.

## Build a useful reference set
Choose complementary views covering silhouette and major connections, not an arbitrary large image count. Identify each image's provenance, variant, angle, useful region, and uncertainty. Do not download or rehost material contrary to access/licensing terms; a reference URL does not license redistribution of its imagery.

Build a short variant sheet: must-have visible features; must-not-have features from neighbouring variants; uncertain equipment. For a Leopard 2A4 task, verify the characteristic turret profile and equipment against actual sources rather than importing later-variant features from generated art. Do not bake unverified real dimensions into this skill.

## Reconcile generated views
Use the approved image as conditioning/edit reference when deriving additional views. Request unchanged design, material palette, attachments, counts, and silhouette. Inspect all views: image generators may disagree about hidden surfaces or apparent orthographic projection.

Give each conflict a resolution: governing source/view, design decision, dependent assemblies. Treat hidden geometry as a conservative inference, not observed fact. A concept can require repair; explain departures needed to resolve visual impossibilities. Do not repeatedly redesign already approved primary forms.

## Image approval
Check complete framing; readable shaded forms; coherent repeated parts; supported fittings; clear silhouette; no confusing pseudo-detail. Present defects/inferences with the image. Record the exact approved filename/version and the user's actual approval or explicit delegation. A generated image file alone does not mean approval.
